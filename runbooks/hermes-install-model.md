# Hermes Agent — Install & Surfaces (Current State)

**Last updated:** 2026-08-01
**Applies to:** zephyr (and any host running the interactive Hermes TUI/desktop)

## Install model

Hermes is installed via the **user nix profile**, NOT built by nixos-config.

```bash
nix profile install github:NousResearch/hermes-agent
```

This lands SPLIT packages in `~/.nix-profile`:

| Package | What | Path |
|---|---|---|
| `hermes-agent-env` | Python CLI + core libs (`bin/hermes`) | `~/.nix-profile/bin/hermes` |
| `hermes-tui` | Prebuilt Ink TUI bundle | `~/.nix-profile/lib/hermes-tui/dist/entry.js` |
| `hermes-web` | Web dashboard assets | `~/.nix-profile/lib/hermes-web` |
| `hermes-desktop` | Electron desktop app | `~/.nix-profile/bin/hermes-desktop` |

### Why (issue #334)

The NousResearch `hermes-agent` flake's `importNpmLock` offline prefetch of
`@nous-research/ui` is broken (ENOTCACHED), which blocked ALL cluster
builds/deploys. Hermes was ripped out of nixos-config and moved to the profile.

`modules/services/hermes-cli.nix` is now lightweight — it only emits the
`~/.hermes` dir tree, fish completions, and `HERMES_HOME`. It does NOT add
hermes to `environment.systemPackages` (`wrappedHermesBin = null`).

## Surfaces

### CLI — works out of the box
`hermes` / `hermes chat -q "..."`. No glue required.

### TUI — needs `HERMES_TUI_DIR`
The raw `bin/hermes` is the upstream env script; it lacks the `makeWrapper`
`HERMES_TUI_DIR` wiring that the monolithic package has. Without it,
`hermes --tui` / `hermes --resume` fails ("TUI workspace is missing").

Fixed by `~/.config/fish/conf.d/hermes-tui.fish` (generated by
`modules/home-manager/hermes-gateway.nix`, gated on
`programs.hermes-gateway.enable`, default true on zephyr):

```fish
set -gx HERMES_TUI_DIR '/home/j_kro/.nix-profile/lib/hermes-tui'
```

It points at the `~/.nix-profile` symlink, so it self-heals across
`nix profile upgrade`.

### Desktop — `hermes desktop` delegates to `hermes-desktop`
The upstream `hermes desktop` (python `cmd_gui`) probes
`PROJECT_ROOT/apps/desktop` — a read-only nix store path the package does NOT
ship — so it errors with "Desktop GUI source not found".

The real Electron launcher is `hermes-desktop` (on PATH from the profile; it
execs electron on `share/hermes-desktop/dist`). Delegated by
`~/.config/fish/conf.d/hermes-desktop-delegate.fish`:

```fish
function hermes
    if test "$argv[1]" = "desktop" -o "$argv[1]" = "gui"
        command hermes-desktop $argv[2..-1]
    else
        command hermes $argv
    end
end
```

The desktop GUI also has a `.desktop` launcher entry
(`modules/home-manager/hermes-desktop.nix` →
`~/.local/share/applications/hermes-desktop.desktop`, `Exec=hermes-desktop`).

## Upgrades

`nix profile upgrade` changes the `hermes-agent-env` store hash, but the two
fish conf.d files reference the stable `~/.nix-profile` symlink, so the TUI and
desktop keep working with no action.

`hermes doctor` will always warn "venv entry point not found" on nix installs —
ignore it (expected).
